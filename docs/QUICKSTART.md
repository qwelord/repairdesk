# Запуск RepairDesk Studio

## Переносной комплект

1. Используйте Windows 10/11 x64. Распакуйте архив целиком в доступную для записи папку, например `D:\RepairDesk-Studio`.
2. Запустите `RepairDesk.exe`, не перемещая его отдельно от остальных файлов.
3. Первый запуск создаст личный профиль и локальную MariaDB. Интернет и установленный .NET не требуются.
4. Войдите: `admin` / `RepairDesk2026!`. Для других ролей — `reception` или `master`, пароль такой же.
5. Смените демонстрационный пароль в разделе «Настройки».

Docker, Windows-службы, OpenServer и права администратора для штатного переносного запуска не нужны. Сервер базы выбирает свободный порт 33366–33385 и принимает только локальные подключения. HTTP API получает свободный локальный порт автоматически.

Windows WebView2 обычно уже установлен. При его отсутствии программа открывает интерфейс в браузере по умолчанию. Не закрывайте окно RepairDesk до окончания работы: в нём живёт сервер. Без рабочего браузера понадобится WebView2. Для полностью автономного встроенного интерфейса публикация поддерживает `-WebView2Directory` с официальным Fixed Version Runtime.

Школьная политика может запрещать запуск любых EXE с флешки, локальных серверов или неизвестных программ. Приложение не обходит такие ограничения: проверьте комплект на учебном ПК заранее и согласуйте запуск с администратором.

## Где данные

- Studio: `%LOCALAPPDATA%\RepairDesk\studio-v2`.
- Первая версия: `%LOCALAPPDATA%\RepairDesk\portable` — не изменяется.
- Диагностические журналы приложения: `%LOCALAPPDATA%\RepairDesk\logs`.
- Журнал MariaDB: `%LOCALAPPDATA%\RepairDesk\studio-v2\server.log`.

Папка программы содержит код, runtime и шаблоны SQL; данные лежат в профиле конкретного пользователя Windows. При переносе на другой компьютер создаётся новая демонстрационная база. Сначала сохраните SQL-копию через «Настройки», если нужны рабочие данные. Не копируйте `data` работающей MariaDB.

## Внешняя MySQL / OpenServer

Для исходников нужен .NET SDK 8 или новее, для готовой self-contained публикации SDK не нужен. Поддерживаются MySQL 8 и MariaDB 10.6+ с InnoDB и UTF-8.

Используйте **пустую отдельную базу**. В phpMyAdmin последовательно выполните `database/schema.sql`, `database/demo.sql`, `database/benchmarks.sql`. Имя базы в этих скриптах — `repairdesk`. Если база с таким именем уже существует и содержит данные, не запускайте скрипты поверх неё; подготовьте отдельный сервер/экземпляр. Миграций нет.

Создайте отдельного локального пользователя с правами SELECT, INSERT, UPDATE, DELETE на `repairdesk.*`. Root-пароль не помещайте в репозиторий. Рядом с EXE создайте `connection.local.json`:

```json
{
  "Server": "127.0.0.1",
  "Port": 3306,
  "Database": "repairdesk",
  "User": "repairdesk_app",
  "Password": "ваш-локальный-пароль"
}
```

Для внешнего режима не кладите папку `server` рядом с EXE: её наличие включает автоматический переносной сервер. Файл `connection.local.json` исключён из Git. Чужую базу версии 1 Studio отклоняет; схемы не обновляются автоматически.

## Самостоятельный API-хост

```powershell
$env:REPAIRDESK_CONNECTION = 'C:\RepairDesk\connection.local.json'
$env:REPAIRDESK_URL = 'http://127.0.0.1:5180'
dotnet run --project src/RepairDesk.Server -c Release
```

Откройте `http://127.0.0.1:5180` в браузере. Этот режим использует ту же реализацию интерфейса и API, не отдельную имитацию. База должна быть создана заранее.

## Восстановление копии

SQL-копия содержит новую схему и все данные, включая пользователей и хеши паролей. Храните её приватно. Восстановление выполняйте администратором БД в **пустом экземпляре**; не импортируйте поверх действующей базы. Скрипт использует имя `repairdesk`.

Копия не шифруется приложением. При передаче используйте защищённый носитель. Рабочие данные и пароли локального сервера не входят в исходный архив и публичный GitHub.
