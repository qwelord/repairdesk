# Архитектура Studio

## Слои

```text
WPF / WebView2 или браузер
       │ fetch / JSON / cookie
       ▼
ASP.NET Core REST API на 127.0.0.1
       │ DTO, проверка сессии, контроль версии
       ▼
RepairDesk.Data.Repository
       │ параметризованный SQL / транзакции InnoDB
       ▼
MySQL 8 / MariaDB
```

- `RepairDesk.Core`: модели, пароли, правила статусов, совместимость.
- `RepairDesk.Data`: MySqlConnector, SQL, транзакции, сметы и диагностические карты.
- `RepairDesk.Api`: маршруты REST, авторизация, подбор под бюджет, FPS, статические ресурсы клиента.
- `RepairDesk.Desktop`: запуск локальной MariaDB и API, изолированный профиль WebView2. Клиент не вызывает Repository для CRUD.
- `RepairDesk.Server`: альтернативный хост того же API для разработки и браузерного запуска.
- `RepairDesk.Tests`: проверки бизнес-правил и интеграция хранилища.
- `RepairDesk.ApiTests`: модели FPS и настоящие HTTP-запросы к Kestrel с MySQL/MariaDB.

WPF остаётся тонкой оболочкой. Интерфейс написан на HTML/CSS/JavaScript без стороннего UI-фреймворка, сборщика и внешних CDN. Основная бизнес-логика, API и хранение реализованы на C#.

## База без миграций

17 таблиц: `schema_info`, `staff`, `clients`, `parts`, `services`, `games`, `orders`, `order_lines`, `payments`, `order_events`, `stock_moves`, `benchmarks`, `builds`, `build_parts`, `estimates`, `estimate_lines`, `diagnostics`.

Чистая схема создаётся SQL-скриптами `schema.sql`, `demo.sql`, `benchmarks.sql` в указанном порядке. Инициализация отказывается работать с непустой базой. Итоговый `schema_info.version=2`. Studio не запускает ALTER TABLE и не преобразует старую базу. Для старых данных требуется отдельный согласованный перенос; автоматического переноса V1 нет.

## Целостность

- Все значения передаются SQL-параметрами; номера таблиц не принимаются от клиента.
- Обновление заявки блокирует строку `FOR UPDATE` и сверяет `version`. Конфликт возвращает 409, не затирая чужое изменение.
- Добавление детали, списание остатка, изменение версии и запись истории — одна транзакция.
- Смета хранит снимок цены. Черновик не резервирует детали. Применение возможно один раз после согласования; при нехватке любой детали вся операция откатывается.
- Удаление строки и отмена заявки возвращают детали. Выдача требует полной оплаты, отмена — предварительного возврата оплаты.
- Финансовые и складские записи не удаляются из истории. DELETE заявки означает контролируемую отмену, а не физическое удаление.
- Повторное применение сметы и устаревшие запросы не приводят к двойному списанию.
- Удаление клиента с заказами, детали с движениями или остатком блокируется. Услуга в заказе остаётся ценовым снимком после изменения каталога.

## Доступ

Администратор управляет каталогом, командой, копиями и всеми заказами. Приемщик принимает технику, ведёт клиентов, согласует сметы, проводит оплаты и движения. Мастер видит только назначенные ему заявки, ведёт диагностику и ремонт; приём, деньги, выдача, клиенты и склад ему недоступны.

Пароли — PBKDF2 с индивидуальной случайной солью. HttpOnly-cookie живёт восемь часов, SameSite=Strict, без продления. Сотрудник перечитывается из БД при каждом защищённом запросе. Для изменения данных обязателен `X-RepairDesk-Client: studio`; чужой Origin отклоняется, CORS не включён. Вход ограничен по частоте. API привязывается только к `127.0.0.1`, Host проверяется. У клиента строгий CSP; данные перед вставкой в HTML экранируются.

API не предназначен для прямой публикации в Интернет или запуска на VPS без дополнительного проектирования HTTPS, секретов, доступа, журналов и резервирования.

## Алгоритмы

Подбор перебирает CPU, платы и GPU, выбирает совместимые память, накопитель, корпус и БП, учитывает наличие и работу по сборке. Ранжирование использует общие для доступных GPU игры и выбранное разрешение. При одинаковой графической производительности выше стоит более дешёвая конфигурация. Это прозрачная эвристика, не универсальный оптимизатор и не оценка производительности CPU.

FPS — опубликованные замеры либо явно обозначенная интерполяция/оценка с происхождением. Подробности в `BENCHMARKS.md`. Программа не проводит аппаратные тесты компьютера и не выполняет произвольные команды из интерфейса.
